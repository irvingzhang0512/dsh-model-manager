# F012 移除插件图片声明，统一宿主原生图片能力

## Purpose

为 dsh-model-manager 的移除插件图片声明，统一宿主原生图片能力维护唯一可编辑的行为与验收规格，保留原编号 F012，区分当前预期、尚未实现设计和历史验证；原始需求、项目资料及旧文档继续原位只读保留。

## Requirements

### Requirement: F012 移除插件图片声明，统一宿主原生图片能力

系统 SHALL 按下列完整场景落实移除插件图片声明，统一宿主原生图片能力的预期、边界与验收。本节迁入已有功能规则；本次仅迁移文档，没有重新执行产品验收。

#### Scenario: F012-S01 Desktop 契约

- **WHEN** 用户读取图片能力或清理旧图片覆盖
- **THEN** Desktop 契约：不恢复第二套图片覆盖；自动视觉属于组合能力，不能把文本模型标成原生图片支持。旧 image 清理和恢复规则原样保留，原生字段写回覆盖 DeepSeek／pi-ai 真实所有者；见 Desktop 契约第 2、6 节。

#### Scenario: F012-S02 界面与运行

- **WHEN** 用户读取图片能力或清理旧图片覆盖
- **THEN** 界面与运行：模型卡片移除“插件图片声明”下拉；图片实测建议、工具／HTTP 返回的新建议和应用结果不再有 pluginImage。模型目录、AUTO 筛选、受管理请求和视觉路由只读取宿主原生声明；旧 capability.image 不参与能力或引用校验。保留原生声明编辑、搜索补全、实测证据、图片辅助功能及策略。

#### Scenario: F012-S03 旧配置处理

- **WHEN** 用户读取图片能力或清理旧图片覆盖
- **THEN** 旧配置处理：models[复合键].capability.image 全部类型和值均为退役字段，不自动复制成宿主图片能力。启动只识别、不改原始运行配置。发现遗留字段时在模型页显示可消失的清理提示，独立预览 clearLegacyImageOverrides，明确选中并应用后仅 unset 这些叶字段；已知空 capability／模型包装可随清理移除，其他属性与未知键保留。不要求目标模型仍加载或 Provider 可写。清理事务整体备份原始值及存在状态，后续编辑拒绝恢复。

#### Scenario: F012-S04 普通保存与恢复

- **WHEN** 用户读取图片能力或清理旧图片覆盖
- **THEN** 普通保存与恢复：待清理旧字段不作为编辑项，不增加新值；普通保存保持原始退役字段直到明确清理，避免绕过清理预览与备份，运行始终忽略。清理后迁移／普通保存／官方或手动目录合并不得复活。恢复旧备份可以还原历史原始值，但字段仍停用，清理提示重新出现；不能通过恢复重新开启插件图片覆盖。其他 capability 属性不退役。

#### Scenario: F012-S05 验收

- **WHEN** 用户读取图片能力或清理旧图片覆盖
- **THEN** 验收：旧覆盖 yes／no／unknown／非法值与原生声明相反时，图片路由、AUTO 及辅助目标判断均只用 nativeImage；无原生声明时保持未知；探测通过只给宿主建议，失败不写能力；卡片没有第二个图片下拉；清理覆盖当前／失效模型、未知嵌套键、空包装、草稿、并发、回滚／恢复与旧备份；清理后重复迁移／保存不复活。
