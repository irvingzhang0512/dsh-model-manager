# F001 模型目录与能力声明

## Purpose

为 dsh-model-manager 的模型目录与能力声明维护唯一可编辑的行为与验收规格，保留原编号 F001，区分当前预期、尚未实现设计和历史验证；原始需求、项目资料及旧文档继续原位只读保留。

## Requirements

### Requirement: F001 模型目录与能力声明

系统 SHALL 按下列完整场景落实模型目录与能力声明的预期、边界与验收。本节迁入已有功能规则；本次仅迁移文档，没有重新执行产品验收。

#### Scenario: F001-S01 Desktop 契约

- **WHEN** 用户读取、刷新或编辑模型目录
- **THEN** Desktop 契约：目录按实际连接所有者读写，显示声明／手改／资料／实测来源；支持 F013 接入预览。推理继续读真实 Provider 的 reasoning.efforts，逻辑入口只声明可达候选档位交集，不复制第一候选能力。图片只用宿主原生声明；具体字段、所有权与验收见 Desktop 契约第 1–3 节。

#### Scenario: F001-S02 行为与边界

- **WHEN** 用户读取、刷新或编辑模型目录
- **THEN** 增加 F011 的模型参数及逐字段来源展示，区分用户显式值、内置目录与兜底默认；不将当前容量、名称或能力声明当作官方证据。API ID 不变，自定义名称及已有不同值默认不选中替换。用户已明确确认本版，实际验证与限制见 V1-COVERAGE。

#### Scenario: F001-S03 行为与边界

- **WHEN** 用户读取、刷新或编辑模型目录
- **THEN** API ID 是真实调用标识，显示名称是宿主选择器展示文本。复合主键仍为 Provider＋ID，名称可重复；普通改名不修改 ID、请求参数或配置引用。提供宿主可编辑目录的新增／改名／删除，具体规则见 F010。

#### Scenario: F001-S04 本次变更

- **WHEN** 用户读取、刷新或编辑模型目录
- **THEN** 本次变更：可读的受管理具体模型标识已实现（0.5.0）；GUI 验收单独记录。

#### Scenario: F001-S05 场景与预期

- **WHEN** 用户读取、刷新或编辑模型目录
- **THEN** 场景与预期：按 Provider＋Model 识别模型，呈现宿主目录、能力声明、手动覆盖与验证证据；逻辑入口和具体实际模型可追溯。

#### Scenario: F001-S06 边界与异常

- **WHEN** 用户读取、刷新或编辑模型目录
- **THEN** 边界与异常：能力声明与实测证据分开；网络错误不能自动否定／肯定能力；同名不同 Provider 不合并。

#### Scenario: F001-S07 验收条件

- **WHEN** 用户读取、刷新或编辑模型目录
- **THEN** 验收条件：复合标识唯一；覆盖不损坏原模型未知字段；声明和验证结果分别显示。

#### Scenario: F001-S08 可读标识预期

- **WHEN** 用户读取、刷新或编辑模型目录
- **THEN** 可读标识预期：新生成的受管理具体模型 ID 使用分别 URI 转义的平台 ID／模型 ID；常见模型在新生成的路由摘要中可读，例如 `dsh-model-manager/arkcli-coding-plan/deepseek-v4-1-flash`。`dsh-model-manager` 仍表示管理插件入口，不改为实际 Provider 名称；AUTO 和别名保留其逻辑入口。

#### Scenario: F001-S09 可读标识边界

- **WHEN** 用户读取、刷新或编辑模型目录
- **THEN** 可读标识边界：仅修改本插件生成／解析模型 ID 的逻辑，不修改 DSH 核心或通知显示层，不自动改写已存历史提示或已有宿主选择。旧 Base64url 标识继续可调用；空字段、非法 URI 转义和无效标识明确拒绝。具体格式见 [可读受管理模型标识契约](../../../docs/ARCHITECTURE.md#可读受管理模型标识契约)。

#### Scenario: F001-S10 本次验收

- **WHEN** 用户读取、刷新或编辑模型目录
- **THEN** 本次验收：新旧标识解析到相同的具体 Provider／Model；不同平台同名模型不冲突；斜杠、百分号、冒号和 Unicode 字符可往返；非法输入不调用底层模型。development 专用会话的新生成提示应出现可读标识，旧标识仍可使用。

### Requirement: F001-Desktop 3. 推理参数与逻辑入口（F001／F002／F003／F012）

系统 SHALL 遵守已确认并实现的 Desktop 契约；本节替代对应旧平台接口与旧默认表述，不恢复已退役能力。

#### Scenario: F001-Desktop-S01 3. 推理参数与逻辑入口（F001／F002／F003／F012）

- **WHEN** 用户读取、刷新或编辑模型目录
- **THEN** 满足以下完整契约：

- 真实模型只读 resolveModelInfo().reasoning.efforts，展示实际 ID、名称、默认及来源；无声明只显示“模型默认”。不按模型名字推测或把接口接受值说成不同真实强度。
- 推理参数优先级：明确本轮／会话覆盖，其次别名候选 efforts，再次 AUTO 规则／执行档，最后具体模型已有默认。未指定表示省略请求字段；显式值不支持该候选时记录并跳过，不默默降级。旧 tier 仅参与原迁移兼容。
- alias／AUTO 的原生选择器只声明全部可达执行候选共同支持的档位；交集为空仅显示默认。最终调用仍校验具体候选，不能复制第一个候选的 reasoning 或最大输出为整个池的能力。用户仍可在管理器为每候选配置各自档位。
- 所有受管理入口保留目标 Provider 的公开请求准备、图片预算、工具更新／重放及成功 replayState。版本 0.2 的规范消息／流／失败结构按实际类型接入，不靠旧字段断言或统一 NETWORK 掩盖结构化错误。
