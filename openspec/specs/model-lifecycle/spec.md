# F010 模型生命周期管理

## Purpose

为 dsh-model-manager 的模型生命周期管理维护唯一可编辑的行为与验收规格，保留原编号 F010，区分当前预期、尚未实现设计和历史验证；原始需求、项目资料及旧文档继续原位只读保留。

## Requirements

### Requirement: F010 模型生命周期管理

系统 SHALL 按下列完整场景落实模型生命周期管理的预期、边界与验收。本节迁入已有功能规则；本次仅迁移文档，没有重新执行产品验收。

#### Scenario: F010-S01 Desktop 契约

- **WHEN** 用户新增、改名、删除或迁移模型
- **THEN** Desktop 契约：来源接入作为 origin=source 的目录事务；新增 AUTO 规则目标及其推理参数纳入删除／迁移／恢复，来源关联不隐式删除仍可调用 Provider。跨所有者逐步 CAS／回滚冲突诚实报告；图片字段保存保留其他模态。旧目录能力、默认输出保护与未知键规则继续有效。

#### Scenario: F010-S02 范围

- **WHEN** 用户新增、改名、删除或迁移模型
- **THEN** 范围：DeepSeek 官方及 llm-pi-ai 宿主已公开的可写模型目录；根据 configurable provider 公开的 settingsNs／settingsPath 定位实际唯一 entry 并按其可写字段识别操作权限，其他契约未知或不可写 Provider 显示具体原因，不假造修改成功。不新增 Provider、密钥或 API 端点。

#### Scenario: F010-S03 新增

- **WHEN** 用户新增、改名、删除或迁移模型
- **THEN** 新增：选择已有可配置 Provider，输入非空 API ID、可选非空显示名称和必要属性，按宿主契约使用合法默认值，缺少协议／端点等 Provider 前置条件时提示先配置 Provider。新增只是本地目录条目，不代表远端账号可调用，不自动请求 API 或 LLM。ID 已存在时提示编辑已有条目，不重复创建；跨 Provider 同 ID 合法。

#### Scenario: F010-S04 改名

- **WHEN** 用户新增、改名、删除或迁移模型
- **THEN** 改名：仅写宿主展示 name 和来源元信息，不改 API ID 或使用引用；名称可重复、支持中文。手动名称后续官方同步保护。已有 API ID 只读，模型替代通过整体迁移处理。

#### Scenario: F010-S05 删除

- **WHEN** 用户新增、改名、删除或迁移模型
- **THEN** 删除：按 F004／F007 分类检查引用，附属设置清理明确列出并由勾选删除确认。普通引用替代可跨 Provider，宿主 defaultModel 的 provider 和 model 必须一起变更，目标模型自己的目录声明保持。明确不兼容的推理参数须改选支持档位或模型默认；未知能力不推断为支持，不静默降档。无替代不能留下仍指向已删对象的配置。

#### Scenario: F010-S06 目录语义

- **WHEN** 用户新增、改名、删除或迁移模型
- **THEN** 目录语义：删除修改真实宿主目录，不是只隐藏插件卡片；llm-pi-ai 清单为空会恢复内置目录，禁止删最后一个模型。默认清单需物化为显式数组时保留有效目录和原用户覆盖，不能使未操作的模型消失或把运行时字段写入配置。

#### Scenario: F010-S07 保存

- **WHEN** 用户新增、改名、删除或迁移模型
- **THEN** 保存：原始配置构建完整写集，保留凭据、输出上限和未知字段。应用前校验 token、目录指纹、受影响配置所有者的 revision、未来覆盖、宿主字段组合和引用参数；整体备份与串行写入，失败按已写版本逆序安全回滚，恢复拒绝覆盖后续编辑。目标存在的官方迁移、视觉开关／引用和删除不可拆开勾选。

#### Scenario: F010-S08 验收

- **WHEN** 用户新增、改名、删除或迁移模型
- **THEN** 验收：新增、中文改名、名称重复、ID 重复、跨 Provider 同 ID、选择器更新与重启后持久化；默认目录物化、最后模型限制、自定义名称保护、附属设置清理；F004 全部图片辅助删除场景；完整普通引用迁移、跨 Provider 参数兼容、重复候选、冲突选择与重复同步无差异；无效输入、过期 token、并发修改、写入／回滚／恢复故障不留半完成配置。
