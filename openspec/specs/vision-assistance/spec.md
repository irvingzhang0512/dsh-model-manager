# F004 视觉原生与 Sidecar

## Purpose

为 dsh-model-manager 的视觉原生与 Sidecar维护唯一可编辑的行为与验收规格，保留原编号 F004，区分当前预期、尚未实现设计和历史验证；原始需求、项目资料及旧文档继续原位只读保留。

## Requirements

### Requirement: F004 视觉原生与 Sidecar

系统 SHALL 按下列完整场景落实视觉原生与 Sidecar的预期、边界与验收。本节迁入已有功能规则；本次仅迁移文档，没有重新执行产品验收。

#### Scenario: F004-S01 Desktop 契约

- **WHEN** 用户发送图片、调用图片工具或管理视觉目标
- **THEN** Desktop 契约：新增自动辅助模式；原生优先时原生模型直接看图，文本／混合别名提前准备必要的视觉摘要。摘要经公开 pre-step 接纳，带附件和视觉来源进入会话；不改用户原话，不在适配器中悄悄注入。工具图片、缓存、历史追问与裁剪保留；辅助失败阻止带图主请求并明确报错。完整策略及验收见 Desktop 契约第 6 节。

#### Scenario: F004-S02 行为与边界

- **WHEN** 用户发送图片、调用图片工具或管理视觉目标
- **THEN** 删去第二套插件图片声明及其运行优先级；NativeFirst／SidecarFirst／NativeOnly／SidecarOnly 统一读取宿主原生图片能力。视觉辅助开关、目标和策略保留，原生支持时仍可按策略选择辅助，图片工具及历史附件行为保持。

#### Scenario: F004-S03 行为与边界

- **WHEN** 用户发送图片、调用图片工具或管理视觉目标
- **THEN** 视觉目标在辅助关闭时仍可查看、替换及明确清除，展示旧视觉兜底及清除入口；清除当前目标且存在旧兜底时明确处理兜底，不能呈现未设置却仍暗中沿用旧目标。失效别名／模型在选择器中保留原值并显示原因，不以空白替代实际配置。

#### Scenario: F004-S04 别名删除中的图片引用

- **WHEN** 用户发送图片、调用图片工具或管理视觉目标
- **THEN** 别名删除中的图片引用：实际当前辅助目标指向被删别名时，提供替换原生支持图片的真实模型、关闭辅助并清除相关目标、取消；辅助已关闭时可只清理遗留目标。当前目标为无关有效模型时，单独清除同名旧兜底不修改 enabled／policy／当前目标。

#### Scenario: F004-S05 本次验收

- **WHEN** 用户发送图片、调用图片工具或管理视觉目标
- **THEN** 本次验收：开启与关闭均可清理目标；无效选项可见且清除后确实从配置移除；仅删除旧兜底不会关闭当前有效视觉辅助，整体删除与恢复覆盖图片引用。

#### Scenario: F004-S06 行为与边界

- **WHEN** 用户发送图片、调用图片工具或管理视觉目标
- **THEN** 图片辅助模型的存在不阻止删除无关模型。删除对象被视觉目标、别名间接目标或旧 roles.vision 兜底引用时，预览展示完整引用链，提供替换图片辅助模型、关闭视觉辅助并删除、取消删除。替代可跨 Provider，但须是声明原生支持图片的真实模型；未知／仅文本模型不能作为视觉替代。

#### Scenario: F004-S07 删除与关闭

- **WHEN** 用户发送图片、调用图片工具或管理视觉目标
- **THEN** 删除与关闭：同一组操作内设置 vision.enabled=false，并清除指向删除对象的视觉目标及旧视觉兜底；已关闭辅助但遗留目标仍引用删除对象时允许清理。不自动删除共享别名；别名候选、默认模型等其他使用引用未处理时仍阻止该组。仅关闭辅助不能隐式清除无关配置。官方替代目标不支持图片或能力未知时，视觉引用须单独换目标或关闭，不能随普通引用直接迁移。

#### Scenario: F004-S08 本次验收

- **WHEN** 用户发送图片、调用图片工具或管理视觉目标
- **THEN** 本次验收：无关模型删除不改视觉配置；直接、别名间接、旧兜底及关闭后遗留引用均可定位；图片替换／关闭与删除整体应用及整体恢复；未处理的其他引用仍阻止。关闭辅助后后续请求按已有关闭规则处理，文本模型不再获得图片辅助；已开始的请求与历史图片证据不重写。

#### Scenario: F004-S09 场景与预期

- **WHEN** 用户发送图片、调用图片工具或管理视觉目标
- **THEN** 场景与预期：配置 NativeFirst／SidecarFirst 策略处理图片附件；model_manager_inspect_image 提供图像检查、裁剪等受控辅助。

#### Scenario: F004-S10 边界与异常

- **WHEN** 用户发送图片、调用图片工具或管理视觉目标
- **THEN** 边界与异常：保留附件引用，检查失败不作为成功缓存；视觉路径不等于原生 Subagent，也不添加旧固定角色委派工具。

#### Scenario: F004-S11 验收条件

- **WHEN** 用户发送图片、调用图片工具或管理视觉目标
- **THEN** 验收条件：原生与 Sidecar 顺序符合策略；图像结果可关联来源；检查失败可重试且不返回旧成功。

### Requirement: F004-Desktop 6. 自动视觉与会话记录（F004／F005／F008／F012）

系统 SHALL 遵守已确认并实现的 Desktop 契约；本节替代对应旧平台接口与旧默认表述，不恢复已退役能力。

#### Scenario: F004-Desktop-S01 6. 自动视觉与会话记录（F004／F005／F008／F012）

- **WHEN** 用户发送图片、调用图片工具或管理视觉目标
- **THEN** 满足以下完整契约：

- vision.enabled／policy／target 保持。新增 automatic：开启时在原生优先下直接处理原生图片，非原生候选自动调用配置的视觉模型；关闭 automatic 则保留原来的显式图片工具路径。原生限定／辅助优先／辅助限定继续有效。
- 先在 agent/pre-step 处理已接纳新输入和当前步骤工具结果的图片；使用目标版本公开 deriveMessages 获取历史，不能依赖已退役同步会话事件快照。在消息提交前完成必要辅助，通过 PreStepDecision.messages 添加独立的 user-role 来源消息，不改原用户内容和旧日志。
- 注册 MessageSourceMap 的 model-manager-vision，来源声明 form='notice'、summary、附件编号及实际视觉 Provider／Model；摘要正文标记为图片观察资料，图片或摘要中的指令不获得用户／系统权限。该上下文和主模型看到的文字一致并进入原生会话记录，不伪造主模型工具调用。
- 自动摘要按本轮问题组织。混合能力别名只要本轮可能到达文本候选，调用前准备辅助，保证后续回退无须在适配器内部注入未记录的新摘要；全部原生候选且 native-first 时不增加辅助调用。
- 缓存键包含 session、图片内容哈希、问题、裁剪区域、视觉候选签名和本次相关配置。相同键并发合并，跨会话不复用；后续具体追问通过保留的 inspect_image 工具重新看原图。缓存不冒充原图、当前事实或已完成验证。
- 视觉目标可为有原生图片能力候选的别名；复用冷却／恢复规则且禁止再次进入自动视觉。没有合格视觉候选、失败、空结果或取消均不写成功缓存；失败阻止本次带图主请求并明确说明，不能当无图继续。
- 新图、工具图片、多图、历史追问、裁剪、原生到文本的别名回退及停止都验收。超限沿用实际 Provider 限制，不无限拆请求规避；原图继续由 AttachmentStore 保存。
