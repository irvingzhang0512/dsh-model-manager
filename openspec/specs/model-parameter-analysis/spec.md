# F011 用 LLM 补全与校正已有模型参数

## Purpose

为 dsh-model-manager 的用 LLM 补全与校正已有模型参数维护唯一可编辑的行为与验收规格，保留原编号 F011，区分当前预期、尚未实现设计和历史验证；原始需求、项目资料及旧文档继续原位只读保留。

## Requirements

### Requirement: F011 用 LLM 补全与校正已有模型参数

系统 SHALL 按下列完整场景落实用 LLM 补全与校正已有模型参数的预期、边界与验收。本节迁入已有功能规则；本次仅迁移文档，没有重新执行产品验收。

#### Scenario: F011-S01 Desktop 契约

- **WHEN** 用户筛选模型并分析、选择及应用参数建议
- **THEN** Desktop 契约：保留搜索补全的独立临时参数及逐字段证据，不把接入目录和统一七档声明当官方能力。能力只写公开原生字段，来源刷新及补全各自保护草稿和未知字段；见 Desktop 契约第 2、3 节。实际请求证据仍独立于建议。

#### Scenario: F011-S02 场景与预期

- **WHEN** 用户筛选模型并分析、选择及应用参数建议
- **THEN** 场景与预期：现有 Provider 导入模型后，用户不清楚模型参数，可按 ID／名称筛选、勾选目标，点击分析，由豆包搜索查平台官方资料，独立 LLM 给出逐字段建议，再预览并一次应用选中修改。最终主键为 Provider＋模型 ID，名称可重复；模型 ID 不改，不新增／删除模型。

#### Scenario: F011-S03 字段范围

- **WHEN** 用户筛选模型并分析、选择及应用参数建议
- **THEN** 字段范围：llm-pi-ai 的 name、contextWindow、maxTokens、input、reasoningEfforts 和当前协议允许的全部 compat 字段；DeepSeek 官方只提供其公开模型契约允许的字段，不伪造 reasoningEfforts／compat。其他未适配 Provider 展示不可写原因，不能绕过宿主写配置。完整字段与合法值按架构同版字段表确定；Provider 地址、协议、凭据、超时、重试、默认推理等运行偏好不在补全范围。

#### Scenario: F011-S04 判断依据

- **WHEN** 用户筛选模型并分析、选择及应用参数建议
- **THEN** 判断依据：实际读取的对应平台原文优先，字段分别记录 official／knowledge／unknown；搜索摘要只作线索，资料不足可知识兜底。冲突的官方资料保持未知，不由知识推翻。没有足够判断时无建议，不把字段缺失推断为 false，不把基础模型能力自动套给平台接口。网页指令只作资料，校验引文不表示程序保证事实正确。

#### Scenario: F011-S05 预览规则

- **WHEN** 用户筛选模型并分析、选择及应用参数建议
- **THEN** 预览规则：展示当前值及 user／catalog／provider-default／runtime-default／unknown 来源、建议值、理由、证据、写入字段及影响。仅官方证据支持且没有用户显式值／有效非默认目录值冲突的缺失项默认选中；已有不同值、自定义或来源不明名称、知识建议默认不选。maxTokens 始终默认不选，并说明模型级配置会成为请求默认输出上限。false 是明确建议值，unknown 不写值。

#### Scenario: F011-S06 核心搜索项

- **WHEN** 用户筛选模型并分析、选择及应用参数建议
- **THEN** 核心搜索项：原生图片 input／inputModalities、上下文容量 contextWindow、模型最大输出 maxTokens、推理档位及 wire 映射 reasoningEfforts 均进入同一目标的官方搜索与 LLM 分析，不因导入后已有默认值或显示档位而跳过。其余公开模型字段与协议 compat 仍在范围内。搜索不足时沿用知识兜底标记及默认不选规则；没有证据不把导入默认改写成官方规格。

#### Scenario: F011-S07 选择与冲突

- **WHEN** 用户筛选模型并分析、选择及应用参数建议
- **THEN** 选择与冲突：可按字段及 compat 叶字段选择，reasoningEfforts 作为完整映射整体选择，不能混拼档位。改选只重算冻结资料的写集，不重跑搜索／LLM。视觉目标、已有 AUTO／别名／旧有效主模型及未来会话推理选择冲突时，预览明确替换／关闭／改档位／用默认；未解决项不可应用，可跳过该模型。插件图片覆盖按 F012 退役，不再作为图片能力来源或同步选项。名称建议采用时同步来源标记；保留独立输出限制、未知字段及停用历史偏好。

#### Scenario: F011-S08 执行规则

- **WHEN** 用户筛选模型并分析、选择及应用参数建议
- **THEN** 执行规则：搜索使用 Agent Plan 豆包搜索和 DSH 凭据引用。默认宿主真实分析模型、模型默认推理档位；临时时限默认 180 秒，允许 30–600 整数秒，每轮整体截止，绕过 AUTO／别名。目标串行，每目标最多两次搜索、三个正文页面、两轮 LLM，不自动重试或请求目标测试图片。显示进度、实际搜索／分析次数和失败原因；单项失败继续，取消／整体失败不写配置。

#### Scenario: F011-S09 保存与恢复

- **WHEN** 用户筛选模型并分析、选择及应用参数建议
- **THEN** 保存与恢复：分析／选择／取消不写模型配置。应用仅写当前 token 选中字段及明确解决的依赖引用；合法 models／modelOverrides 原始层、完整备份、CAS／目录与未来覆盖校验、串行事务、安全回滚与后续编辑保护复用 F010。分析期间基线变化使预览失效；恢复保守拒绝跨重启 revision 不匹配。保留凭据、其他模型及未选参数，无关插件草稿按实际写集保护，不将有效默认层全量落盘。

#### Scenario: F011-S10 验收

- **WHEN** 用户筛选模型并分析、选择及应用参数建议
- **THEN** 验收：重名／跨 Provider 同 ID 隔离；全部模型字段、完整推理映射、不同协议 compat；来源判定、真实 false、嵌套合并、未知参数拒绝、ID 不变、自定义名称和 maxTokens 不默认替换；引文核验／知识兜底／未知／资料冲突／搜索缺凭据与错误／超时／取消／部分失败；字段联动、原生图片／视觉／有效推理引用冲突、草稿保护、并发拒绝、回滚与恢复；旧 v1／v2／v3 保存不新增空设置或复活退役字段。截图中的容量和档位仅是当前显示值，不作为型号已核实事实。
