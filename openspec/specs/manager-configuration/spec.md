# F008 配置迁移、覆盖与日志

## Purpose

为 dsh-model-manager 的配置迁移、覆盖与日志维护唯一可编辑的行为与验收规格，保留原编号 F008，区分当前预期、尚未实现设计和历史验证；原始需求、项目资料及旧文档继续原位只读保留。

## Requirements

### Requirement: F008 配置迁移、覆盖与日志

系统 SHALL 按下列完整场景落实配置迁移、覆盖与日志的预期、边界与验收。本节迁入已有功能规则；本次仅迁移文档，没有重新执行产品验收。

#### Scenario: F008-S01 Desktop 契约

- **WHEN** 用户载入、迁移或保存管理器配置
- **THEN** Desktop 契约：v1／v2／v3 有效迁移至 v4，原始用户层不在只读启动时改写；新增来源关联、别名 recovery、AUTO rules／evaluatorReasoningEffort、vision.automatic。健康状态单独按实际 Profile 保存，旧原始字段的显式清理／恢复不变；新 AUTO 规则纳入完整引用规划。字段默认、迁移及旧备份限制见 CONFIG 与 Desktop 契约。

#### Scenario: F008-S02 行为与边界

- **WHEN** 用户载入、迁移或保存管理器配置
- **THEN** 旧模型图片覆盖作为已退役已知字段处理，运行／迁移／保存均不得复活；原始字段的显式清理与备份按 F012，同名其他 capability 属性、tiers／legacyTiers 及未知键保留，不把旧图片值移到宿主。

#### Scenario: F008-S03 本次变更

- **WHEN** 用户载入、迁移或保存管理器配置
- **THEN** 本次变更：新旧受管理模型标识兼容及相关回归已实现（0.5.0）。

#### Scenario: F008-S04 场景与预期

- **WHEN** 用户载入、迁移或保存管理器配置
- **THEN** 场景与预期：v1/v2/v3 迁移至 v4 保留模型、别名、视觉、旧主模型、候选档位与手动覆盖；记录实际选择和调用日志。

#### Scenario: F008-S05 边界与异常

- **WHEN** 用户载入、迁移或保存管理器配置
- **THEN** 边界与异常：迁移幂等；fast／balanced／deep 仅为旧值迁移，不恢复为新配置入口；reasoningEffort 必须是模型公开值。

#### Scenario: F008-S06 验收条件

- **WHEN** 用户载入、迁移或保存管理器配置
- **THEN** 验收条件：重复迁移不丢配置；旧档位映射后具体候选保留；新 AUTO 默认不带来额外评估。

#### Scenario: F008-S07 标识兼容

- **WHEN** 用户载入、迁移或保存管理器配置
- **THEN** 标识兼容独立于 v1–v4 配置升级：具体模型引用对象和存储用 `modelKey()` 保持原格式，可读路由标识本身不触发设置／凭据／历史会话迁移。读取旧标识仅解码，不主动转换宿主选择，不重写历史日志、验证证据和视觉缓存。

#### Scenario: F008-S08 本次验收

- **WHEN** 用户载入、迁移或保存管理器配置
- **THEN** 本次验收：主请求与受管理子任务的新生成路由使用可读 ID，旧 ID 仍路由到原模型；AUTO／别名和请求快照行为不变。官方同步应用迁移后，配置引用及模型键仍按 F007 迁移，新生成的受管理路由指向目标模型；备份／恢复保留原写集及字段值。
