# F015 统一版本与固定交付

## Purpose

为 dsh-model-manager 的统一版本与固定交付维护唯一可编辑的行为与验收规格，保留原编号 F015，区分当前预期、尚未实现设计和历史验证；原始需求、项目资料及旧文档继续原位只读保留。

## Requirements

### Requirement: F015 统一版本与固定交付

系统 SHALL 按下列完整场景落实统一版本与固定交付的预期、边界与验收。本节迁入已有功能规则；本次仅迁移文档，没有重新执行产品验收。

#### Scenario: F015-S01 行为与边界

- **WHEN** 用户核对固定包、安装来源或组合启停
- **THEN** 包版本统一为 0.2.1-rc.2+rev.1；宿主与官方 peers 仍为实际要求的原版本。完整字符串、源码 SHA 和产物散列同时校验，不能使用忽略 build metadata 的 SemVer 判断修订升级。

#### Scenario: F015-S02 行为与边界

- **WHEN** 用户核对固定包、安装来源或组合启停
- **THEN** Chatty／Automation 的原比较接口保留，规范后缀改为 +rev.N，N 为无前导零的安全正整数；跨官方基线拒绝。旧版本仅由明确迁移映射及原锁／散列接管，不能把旧后缀 .1 与 rev.1 当作无需更新。

#### Scenario: F015-S03 行为与边界

- **WHEN** 用户核对固定包、安装来源或组合启停
- **THEN** 本包继续独立安装，不进入办公套件；启停和业务配置语义保持。

#### Scenario: F015-S04 配置／数据

- **WHEN** 用户核对固定包、安装来源或组合启停
- **THEN** 配置／数据：没有业务字段改名或存储搬迁；套件接管仅处理组合选择与既有 disabled 字段，保留未知配置、工具引用、文档和凭据。迁移 CAS／备份／冲突／回滚由根维护入口执行。

#### Scenario: F015-S05 验收

- **WHEN** 用户核对固定包、安装来源或组合启停
- **THEN** 验收：完整产物、版本迁移、原功能回归；成员还需唯一实例、旧配置命中、总／子开关与业务资料保留。具体记录见 VERIFICATION-OFFICE-20261018.md（完成后生成）。
