# F006 验证、探测与推荐草稿

## Purpose

为 dsh-model-manager 的验证、探测与推荐草稿维护唯一可编辑的行为与验收规格，保留原编号 F006，区分当前预期、尚未实现设计和历史验证；原始需求、项目资料及旧文档继续原位只读保留。

## Requirements

### Requirement: F006 验证、探测与推荐草稿

系统 SHALL 按下列完整场景落实验证、探测与推荐草稿的预期、边界与验收。本节迁入已有功能规则；本次仅迁移文档，没有重新执行产品验收。

#### Scenario: F006-S01 行为与边界

- **WHEN** 用户显式验证模型或生成推荐草稿
- **THEN** 探测／验证不再产生 pluginImage 建议，正确识别测试图可给 hostImage 支持建议；被拒、识别失败、网络错误或取消仅保存证据，不推断原生不支持。可应用建议仅写公开宿主声明；不可写 Provider 展示原因，不写回插件覆盖。

#### Scenario: F006-S02 行为与边界

- **WHEN** 用户显式验证模型或生成推荐草稿
- **THEN** 智能补全产生资料／知识建议，不生成真实验证记录；不得把模型资料、LLM 推测或配置保存成功写成图片／工具／推理实测通过。首版不自动发测试图片，不把接口请求成功当参数行为已验证。

#### Scenario: F006-S03 场景与预期

- **WHEN** 用户显式验证模型或生成推荐草稿
- **THEN** 场景与预期：用户显式触发模型验证／图片能力探测，并保存结果证据；推荐功能调用独立模型生成可编辑的三档草稿。

#### Scenario: F006-S04 边界与异常

- **WHEN** 用户显式验证模型或生成推荐草稿
- **THEN** 边界与异常：真实调用会用外部服务，本次不运行；图片临时声明应恢复；不确定失败不改能力；推荐不自动保存设置。

#### Scenario: F006-S05 验收条件

- **WHEN** 用户显式验证模型或生成推荐草稿
- **THEN** 验收条件：中止／失败能恢复临时状态；探测证据与声明分开；推荐草稿需用户保存才写入。
