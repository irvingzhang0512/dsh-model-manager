# F006-Batch 一键批量模型验证

## Purpose

为 dsh-model-manager 的F006-Batch 一键批量模型验证维护唯一可编辑的行为与验收规格，保留原编号 F006，区分当前预期、尚未实现设计和历史验证；原始需求、项目资料及旧文档继续原位只读保留。

## ADDED Requirements

### Requirement: F006-Batch 一键批量模型验证

系统 SHALL 按下列完整场景落实F006-Batch 一键批量模型验证的预期、边界与验收。本节为原有待实现设计的格式迁移，尚未获得实施批准，不作为现有能力。

#### Scenario: F006-S01 入口与范围

- **WHEN** 用户显式验证模型或生成推荐草稿
- **THEN** 入口与范围：模型页提供“一键测试当前筛选结果”，无筛选时覆盖全部已加载真实模型；每个 Provider 提供“测试整个平台”，覆盖平台全部已加载真实模型，不受名称筛选影响。按钮显示模型数，旁边显示预计请求数及真实调用用量提示，点击即开始；空目标禁用，保留单模型入口。

#### Scenario: F006-S02 项目与执行

- **WHEN** 用户显式验证模型或生成推荐草稿
- **THEN** 项目与执行：每模型依次测试文字、工具；仅开始时 nativeImage=yes 的模型追加图片，no／unknown 显示“不适用”，不临时提权、不写能力声明。最多同时测试两个模型，单项失败继续其他项目；每项总时限 60 秒，不自动重试、不执行推理测试。预计请求数为每模型两次加支持图片模型数。

#### Scenario: F006-S03 进度与停止

- **WHEN** 用户显式验证模型或生成推荐草稿
- **THEN** 进度与停止：显示完成项目／总项目、当前模型及逐项结果；停止取消活动请求，不启动剩余项目，未开始项显示“未执行”，已完成证据保留。关闭页面／面板卸载取消；刷新不续跑，本轮汇总不后台持久化。

#### Scenario: F006-S04 判定与展示

- **WHEN** 用户显式验证模型或生成推荐草稿
- **THEN** 判定与展示：文字正常结束且有非空白输出、工具实际返回调用、图片正确识别测试图颜色分别算“通过”；请求成功但未观察到行为显示“未确认”，其他结果区分失败、超时、取消。当前分组与卡片按项目展示最新有效证据，过期项单列“历史证据过期”，不混入本轮失败。证据仍按模型＋项目保存最近一条，重测替换对应项，其他项目保留。

#### Scenario: F006-S05 配置与草稿

- **WHEN** 用户显式验证模型或生成推荐草稿
- **THEN** 配置与草稿：启动固定目标／项目集合，筛选变化不改变队列；运行锁定当前页面配置写入及重复测试入口，保留其他未保存草稿。验证开始固定配置签名，外部配置变化后结果按既有规则过期，不能使用结束时配置给旧请求签名。完成刷新证据不重置草稿。

#### Scenario: F006-S06 本次验收

- **WHEN** 用户显式验证模型或生成推荐草稿
- **THEN** 本次验收：全部／筛选／平台整组范围、空列表、跨平台同名模型、图片跳过、两个模型并发上限、项目顺序、失败继续、60 秒截止、取消／关闭不续跑；未观察能力不算通过、历史过期不混入本轮失败；配置变化签名、原始设置不变、草稿保护。模拟用例与客户端冒烟完成后，在 development 验证进度、取消及真实调用，未完成实测不声明通过。
