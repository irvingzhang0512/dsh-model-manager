# 批量模型验证设计

## Context

本变更承接原文待确认／待实现内容。文档格式迁移已经授权；产品实施授权未因此扩大。现行功能规格与本变更分开维护，原文各版历史证据保持原样。

## Goals / Non-Goals

- 保留原需求的全部边界、异常、接口和验收条件，依下列规格逐项实施。
- 不在文档迁移时改源码、测试、运行配置、原始需求、业务项目文件或运行 Skill。
- 不以已有 Web／隔离测试外推当前 Desktop 全组合通过，不生成新的用户批准记录。

## Decisions

- [F006 验证、探测与推荐草稿](specs/batch-model-verification/spec.md) 是本变更的完整行为和技术契约；原编号保持可追踪。
- [批量验证队列、接口、签名与证据存储](specs/batch-verification-contract/spec.md) 是本变更的完整行为和技术契约；原编号保持可追踪。
- 技术契约与行为一起审阅；涉及配置必须保留旧用户层、未知字段、完整引用、备份、并发冲突和恢复边界。
- 保存成功、后续登记／展示失败、运行验证与文档结构校验分别报告。

## Risks / Trade-offs

旧材料存在不同日期的状态；通过迁移索引说明替代关系，不能把旧计划标成现状。依赖或调用条件不具备时记录未验证范围，不用模拟证据代替真实服务或界面验收。

## Migration Plan

1. 审阅本目录 specs、技术契约及原文来源，记录明确确认的版本和范围。
2. 按 tasks 实施并验证；保留数据与配置迁移边界，发生语义变化重新确认。
3. 验收后同步主规格和迁移索引再归档；未经实现不能仅因 artifacts ready 而归档为完成。
