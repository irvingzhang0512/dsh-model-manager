## F001 模型目录与能力声明

- 实现状态：已实现。
- 本次变更：可读的受管理具体模型标识已实现（0.5.0）；GUI 验收单独记录。
- 场景与预期：按 Provider＋Model 识别模型，呈现宿主目录、能力声明、手动覆盖与验证证据；逻辑入口和具体实际模型可追溯。
- 边界与异常：能力声明与实测证据分开；网络错误不能自动否定／肯定能力；同名不同 Provider 不合并。
- 验收条件：复合标识唯一；覆盖不损坏原模型未知字段；声明和验证结果分别显示。
- 可读标识预期：新生成的受管理具体模型 ID 使用分别 URI 转义的平台 ID／模型 ID；常见模型在新生成的路由摘要中可读，例如 `dsh-model-manager/arkcli-coding-plan/deepseek-v4-1-flash`。`dsh-model-manager` 仍表示管理插件入口，不改为实际 Provider 名称；AUTO 和别名保留其逻辑入口。
- 可读标识边界：仅修改本插件生成／解析模型 ID 的逻辑，不修改 DSH 核心或通知显示层，不自动改写已存历史提示或已有宿主选择。旧 Base64url 标识继续可调用；空字段、非法 URI 转义和无效标识明确拒绝。具体格式见 [可读受管理模型标识契约](ARCHITECTURE.md#可读受管理模型标识契约)。
- 本次验收：新旧标识解析到相同的具体 Provider／Model；不同平台同名模型不冲突；斜杠、百分号、冒号和 Unicode 字符可往返；非法输入不调用底层模型。development 专用会话的新生成提示应出现可读标识，旧标识仍可使用。
- 实现依据：[../src/domain.ts](../src/domain.ts)、[../src/service.ts](../src/service.ts)、[../src/provider-adapter.ts](../src/provider-adapter.ts)。
- 验证记录：2026-10-03 静态核对；已有测试入口：[../test/domain.test.ts](../test/domain.test.ts)、[../test/service.test.ts](../test/service.test.ts)（覆盖范围以用例为准，本次未执行）。

## F007 官方同步预览与恢复

- 待确认变更（2026-10-10，拟 0.7.0）：每轮分析时限改为独立临时输入，默认 180 秒，可选 30–600 的整数秒；计时覆盖该轮整个 LLM 调用，包括持续推理／流式输出，不因有输出而重置。仍有插件强制截止和及时取消。新增参数不保存、不计草稿、不改用户模型或推理档位；当前运行的 0.6.2 仍固定 60 秒，确认后才实现新默认。
- 待确认边界：非法时限在网页读取／LLM 前拒绝；修改时限作废旧预览，刷新固定本次时限，不能中途延长正在执行的调用。每页获取 10 秒、最多六页三轮、格式／证据／冲突／完整性校验、失败无 token 无写入和手动应用规则保持。不增加自动重试，不自动降低 medium，不保证模型每次都在时限内完成。
- 待确认验收：模拟第二轮读取四页、分析超过 60 秒但未达 180 秒时可正常完成；自选 60 秒时仍在 60 秒结束，持续推理不延长总截止；默认、自选边界、非法类型／越界、取消、旧预览作废、配置不写和正常清理均有回归。必须在日常 DSH 的完整预览链路以 glm-5.3／medium 实测，分别记录实际页面／轮次与结果，不用独立适配器成功代替该证据。

- 实现状态：已实现（0.4.0）；0.6.2 独立真实网页／LLM 完整分析已通过，浏览器成功预览与人工应用／恢复仍待验收。
- 本次变更：已实现（0.6.0）。2026-10-10 用户以“修改吧”明确确认 F007／F009、临时分析架构和配置契约；临时参数及显式推理档位规则替代原草稿保存和自动选择 low，历史验证保留。
- 临时分析参数：资料入口、分析模型和 `reasoning_effort` 仅作为本次预览的页面输入，不写插件设置、不修改宿主模型设置或默认模型，不触发“有未保存修改”。点击刷新无需先保存。旧 `official.sourceUrl`／`official.analyzer` 可用于页面首次初始化，之后更改只保留在当前页面，不自动持久化。
- 推理档位：下拉列表仅使用所选真实模型公开的档位；未选择分析模型时展示宿主默认模型的实际档位。留空表示使用模型默认，请求省略 reasoningEffort；不自动选 low 或其他档位，不改变 Provider 的能力声明。切换分析模型清空已选档位；不公开档位时只显示默认选项。宿主在调用前校验显式档位，不支持时拒绝，不发送 LLM 请求。
- 写入边界：刷新、失败及取消不写模型配置或分析参数；仅用户手动应用选中差异时，按既有写集与安全规则写模型／引用及同步记录。独立分析参数不随应用保存；其他标签页未保存的插件草稿仍需保存或放弃后重新预览，不把临时分析输入当成该草稿。
- 本次验收：更改三项分析输入后保存按钮／草稿状态不变，直接预览携带准确档位；默认不带档位、不自动 low；切换模型清空档位，非法档位在网络／LLM 前拒绝；预览成功、失败、取消均不写配置；无其他草稿时可直接应用选中差异；其他草稿保护、CAS、备份及恢复保持。
- 场景与预期：每次用户点击“刷新并预览”，从本次临时入口重新读取最新 API 资料（旧 `official.sourceUrl` 仅供首次初始化），默认入口为 `https://api-docs.deepseek.com/zh-cn/`。由单独选择的真实 LLM 分析当前可选的 API model name；未选择分析模型时使用宿主默认模型，绕过 AUTO、别名和兜底路由。没有可用分析模型时提示，不调用其他模型代替。
- 资料范围：程序提取正文、表格、脚注和实际链接，LLM 可以要求读取已见页面的相关链接；最多入口加五个补充页面、三轮分析，补充链接与重定向限入口 hostname。允许手动更换 HTTPS 入口和其 hostname，不固定页面路径、表格结构、模型数量、型号或版本。
- 分析结果：返回完整性判断、当前模型清单、旧 ID 的兼容／替代关系、有证据的属性和页面原文。程序校验结果格式、ID 唯一性、来源实际已读取、证据实际存在；当前型号必须有包含该 API model name 的证据。网页指令不能改变分析规则；不凭模型记忆补充清单。历史型号、兼容 ID、代码示例中孤立出现的名称不自动作为当前模型。
- 边界与异常：获取失败、超出读取限额仍不能完成、无效输出、空清单、冲突或完整性不足时，不生成可应用预览，不回退旧清单。未知名称或能力保持未知，不覆盖用户配置；LLM 的完整性判断与原文证据可审阅，不能将程序的格式检查表述为事实正确性保证。刷新立即作废旧预览，分析可取消，取消或失败均不写配置。
- 差异：以最新宿主目录和显式配置比较新增、字段更新、合并迁移、移除。显式模型数组缺失时以有效宿主目录为基线，应用后建立显式数组。仅处理 `llm-deepseek`／`deepseek-official`，第三方 Provider 不参与。
- 合并迁移：仅依据明确官方替代证据；多个旧 ID 指向同一目标时，合为一个操作，包含目标创建／合并、全部引用迁移及旧条目移除。覆盖插件别名、AUTO（含旧 main／roles）、视觉、模型键能力与档位、分析模型配置、宿主默认模型、原生子 Agent 范围及会话／下一轮覆盖。候选去重保留首次出现顺序，模型键同步迁移；用户配置冲突列明具体位置并阻止该操作，调整后重新预览。进行中的请求和本轮已固定选择不改，历史记录、实测证据与缓存不改写成新型号的证据。
- 移除：没有明确替代关系的模型生成单独移除项；配置或未来会话覆盖仍有引用（含模型键用户设置）时列出位置并禁止删除，用户处理后重新预览；未引用时可显式勾选移除。旧 ID 从可选目录移除，不代表禁止宿主直接调用兼容 ID。
- 保存与恢复：应用只执行选中且未阻止的差异，保留凭据、用户输出上限及未知字段；写前检查所有受影响设置 revision 与会话覆盖状态，备份本次写集的原值（含字段是否存在）。多处写入失败时按已写版本安全回滚；遇到并发修改不得强制覆盖。恢复覆盖完整写集，只在同步后的配置／覆盖状态未变化时执行；旧格式备份保留原恢复范围，不补造新字段。
- 验收条件：模拟资料支持模型数增减、新 ID、入口／链接路径改变、不同 HTML 布局；仅根据已读证据确认当前清单并正确合并旧 ID；未引用可删、有引用阻止；重复同步无差异。无效 JSON、编造 ID／证据、信息不足、冲突、网络失败、取消和限额均不写配置；未知能力不变，第三方同名模型与用户字段不变。完整引用迁移、版本冲突、部分写入失败、备份恢复和恢复冲突有回归用例。
- 实现依据：[../src/official-sync.ts](../src/official-sync.ts)、[../src/official-state.ts](../src/official-state.ts)、[../src/official-host.ts](../src/official-host.ts)；技术契约见 [ARCHITECTURE.md](ARCHITECTURE.md#llm-官方同步契约) 和 [CONFIG.md](CONFIG.md#llm-官方同步配置)。
- 验证记录：2026-10-09 typecheck、build 和全部 93 项测试通过；模拟网页／LLM、完整写集及事件流见 official-sync、official-host、official-client 测试。development 页面与真实网页读取通过，LLM 缺凭据明确报错且不提供预览、不写配置；成功真实 LLM 验收待完成。
