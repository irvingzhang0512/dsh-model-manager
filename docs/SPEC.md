## F011 用 LLM 补全与校正已有模型参数

- 文档版本：`model-parameters-20261010-v2`（2026-10-10）；实现基线：0.10.0／`5e33bec0bf1b66aeeac92a79cf86c2d7a3fd301b`；规划功能版本：0.11.0。实现状态：待实现。用户已明确要求实施完整计划，截图作为既有模型卡片的界面参考；本版 SPEC／ARCHITECTURE／CONFIG 的具体契约待用户明确确认，不能把计划实施请求记为随后生成文档已确认。
- 场景与预期：现有 Provider 导入模型后，用户不清楚模型参数，可按 ID／名称筛选、勾选目标，点击分析，由豆包搜索查平台官方资料，独立 LLM 给出逐字段建议，再预览并一次应用选中修改。最终主键为 Provider＋模型 ID，名称可重复；模型 ID 不改，不新增／删除模型。
- 字段范围：llm-pi-ai 的 name、contextWindow、maxTokens、input、reasoningEfforts 和当前协议允许的全部 compat 字段；DeepSeek 官方只提供其公开模型契约允许的字段，不伪造 reasoningEfforts／compat。其他未适配 Provider 展示不可写原因，不能绕过宿主写配置。完整字段与合法值按架构同版字段表确定；Provider 地址、协议、凭据、超时、重试、默认推理等运行偏好不在补全范围。
- 判断依据：实际读取的对应平台原文优先，字段分别记录 official／knowledge／unknown；搜索摘要只作线索，资料不足可知识兜底。冲突的官方资料保持未知，不由知识推翻。没有足够判断时无建议，不把字段缺失推断为 false，不把基础模型能力自动套给平台接口。网页指令只作资料，校验引文不表示程序保证事实正确。
- 预览规则：展示当前值及 user／catalog／provider-default／runtime-default／unknown 来源、建议值、理由、证据、写入字段及影响。仅官方证据支持且没有用户显式值／有效非默认目录值冲突的缺失项默认选中；已有不同值、自定义或来源不明名称、知识建议默认不选。maxTokens 始终默认不选，并说明模型级配置会成为请求默认输出上限。false 是明确建议值，unknown 不写值。
- 核心搜索项：原生图片 input／inputModalities、上下文容量 contextWindow、模型最大输出 maxTokens、推理档位及 wire 映射 reasoningEfforts 均进入同一目标的官方搜索与 LLM 分析，不因导入后已有默认值或显示档位而跳过。其余公开模型字段与协议 compat 仍在范围内。搜索不足时沿用知识兜底标记及默认不选规则；没有证据不把导入默认改写成官方规格。
- 选择与冲突：可按字段及 compat 叶字段选择，reasoningEfforts 作为完整映射整体选择，不能混拼档位。改选只重算冻结资料的写集，不重跑搜索／LLM。视觉目标、已有 AUTO／别名／旧有效主模型及未来会话推理选择冲突时，预览明确替换／关闭／改档位／用默认；未解决项不可应用，可跳过该模型。插件图片覆盖按 F012 退役，不再作为图片能力来源或同步选项。名称建议采用时同步来源标记；保留独立输出限制、未知字段及停用历史偏好。

- 保存与恢复：分析／选择／取消不写模型配置。应用仅写当前 token 选中字段及明确解决的依赖引用；合法 models／modelOverrides 原始层、完整备份、CAS／目录与未来覆盖校验、串行事务、安全回滚与后续编辑保护复用 F010。分析期间基线变化使预览失效；恢复保守拒绝跨重启 revision 不匹配。保留凭据、其他模型及未选参数，无关插件草稿按实际写集保护，不将有效默认层全量落盘。
