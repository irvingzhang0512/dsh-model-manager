# dsh-model-manager

DSH 的模型管理插件：查看模型能力、设置别名与故障兜底、按任务选择主模型，并在需要时调用视觉辅助模型。子 Agent 的启动、后台执行和结果回收由 DSH 原生 Subagent 完成。

## 快速上手

1. 在 DSH 模型选择器中确认所需 Provider 和模型已经加载。在“模型”页检查模型 ID、能力来源和实际推理档位；“验证调用”会发出真实请求，只提供证据，不会自动修改声明。
2. 需要稳定入口时，到“别名与兜底”页按顺序加入具体模型。每个候选可使用其真实支持的推理档位；请求尚无输出时可按设置重试或切换候选。
3. 需要按任务自动换主模型时，在“AUTO 自动选模型”页选择评估模型和简单、常规、复杂三档执行模型，保存并开启，然后在模型选择器选择 `AUTO`。手动选择具体模型会绕过评估。
4. 需要多 Agent 工作时，到“子 Agent”页配置 DSH 原生模型选择范围。主 Agent 自己判断是否拆分任务、拆成几个任务以及子任务使用什么模型。

所有执行档的“推理档位”是所选模型实际公开的值，例如 `off`、`low`、`high`、`max`；留空表示使用模型默认。任务等级和推理档位是两件事。

## AUTO 与 Subagent

AUTO 只评估本轮**主任务**。插件用独立评估模型看最新请求和有限的近期上下文，返回任务等级与理由，然后选择兼容的执行模型。本轮工具循环保持该选择；下一轮用户消息重新评估。评估器不能调用工具，也不会执行任务。评估失败或超时 10 秒时使用常规档；候选能力不符时优先尝试更高档，没有兼容候选则报错。评估器看不到图片内容，图片能力由执行模型目录约束。

Subagent 是 DSH 原生机制。主 Agent 可以不创建子 Agent，也可以创建不限于固定角色名称的多个任务。普通 `subagent` 可选择不同模型和推理强度，并使用宿主的后台运行与结果通知；`subagent_fork` 继承父模型。子 Agent 不会再次触发 AUTO 评估。页面里的“分工偏好”只给主 Agent 提示，不保证执行。

## 常用场景

- **日常聊天与复杂编码混用**：简单档配轻量模型，常规档配日常模型，复杂档配代码／推理模型。日志可查看任务等级、实际模型和选择理由。
- **同一入口有备用模型**：创建别名，按优先顺序加入候选。每个候选分别设定真实推理档位；已有输出或工具操作后不会换模型重做任务。
- **图片与多 Agent**：主模型支持图片时原生处理；不支持时可开启视觉辅助，将图片交给辅助模型理解。并行调研或代码审查由主 Agent 使用原生 Subagent，模型范围在“子 Agent”页设置。

## DeepSeek 官方资料

“模型”页可点击“刷新并预览”读取可调整的 [官方模型表](https://api-docs.deepseek.com/zh-cn/quick_start/pricing)、[思考模式](https://api-docs.deepseek.com/zh-cn/guides/thinking_mode/)和[更新日志](https://api-docs.deepseek.com/zh-cn/updates)。预览列出来源、抓取时间和字段差异；只应用勾选项。资料冲突或解析失败时不覆盖配置。同步仅处理 `llm-deepseek` 官方 Provider，不迁移第三方同名模型；保存前核对 revision，应用前备份，可用“恢复上次同步”撤回。凭据和用户设置的输出上限不会随官方资料刷新而覆盖。

## 常见问题

- **为什么 AUTO 没有创建子 Agent？** AUTO 只选主模型。是否拆分由主 Agent 根据任务决定；原生 Subagent 的模型范围也要单独开启。
- **说“继续”会降到简单档吗？** 评估会带入有限的近期上下文，信息不足时按常规档处理。
- **配置何时生效？** 插件设置对后续请求生效。原生 Subagent 模型范围修改对**新会话**生效；安装或更新插件代码后需重启 DSH。
- **验证失败是否代表模型不支持？** 网络错误、取消和一次拒绝都不能直接改写能力资料。先核对 Provider 声明、模型 ID 和来源，再决定是否手动修改。
- **旧配置怎么办？** v1/v2 启动时迁移为 v3，保留模型、别名、视觉和旧主模型。新 AUTO 未启用前仍使用旧固定主模型，不增加评估调用。
