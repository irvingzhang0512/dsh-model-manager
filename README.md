# dsh-model-manager

当前功能与验收以 [docs/SPEC.md](docs/SPEC.md) 为入口；原始需求保留为历史来源，技术契约见规格内的文档索引。功能任务先改规格与相关技术契约，用户明确确认该版文档后再开发；已确认同一版不重复询问。Bug 按已有且不变的预期查源码修复。


DSH 的模型管理插件：查看模型能力、设置别名与故障兜底、按任务选择主模型，并在需要时调用视觉辅助模型。子 Agent 的启动、后台执行和结果回收由 DSH 原生 Subagent 完成。

## 快速上手

1. 在 DSH 模型选择器中确认所需 Provider 和模型已经加载。在“模型”页检查模型 ID、能力来源和实际推理档位；“验证调用”会发出真实请求，只提供证据，不会自动修改声明。
2. 需要稳定入口时，到“别名与兜底”页按顺序加入具体模型。每个候选可使用其真实支持的推理档位；请求尚无输出时可按设置重试或切换候选。
3. 需要按任务自动换主模型时，在“AUTO 自动选模型”页选择评估模型和简单、常规、复杂三档执行模型，保存并开启，然后在模型选择器选择 `AUTO`。手动选择具体模型会绕过评估。
4. 需要多 Agent 工作时，到 DSH 官方设置配置原生 Subagent 模型范围。主 Agent 自己判断是否拆分任务、拆成几个任务以及子任务使用什么模型；插件不提供重复的子 Agent 配置入口。

所有执行档的“推理档位”是所选模型实际公开的值，例如 `off`、`low`、`high`、`max`；留空表示使用模型默认。任务等级和推理档位是两件事。

从 0.5.0 起，新生成的受管理具体模型标识使用可读的平台／模型 ID，例如 `dsh-model-manager/arkcli-coding-plan/deepseek-v4-1-flash`。前缀表示请求经过模型管理插件；特殊字符分别 URI 转义。旧编码仍可调用，已存历史提示不会自动改写；AUTO 与别名仍显示逻辑入口。

## 模型新增、改名与删除

从 0.8.0 起，“模型”页可新增模型，各模型卡片可修改显示名称或删除。API ID 是调用目标，显示名称是 DSH 展示文本；同一 Provider 内 ID 唯一。重复 ID 会提供“编辑已有模型”。支持 DeepSeek 官方与宿主公开可写的 llm-pi-ai 目录，新增不自动请求 API。

操作先独立预览，再“应用本次修改”，不需要保存所有标签页。只更改宿主目录时保留其他插件草稿；更改插件引用或名称来源标记时先保存或放弃草稿。官方合并已存在目标时，可在预览逐项处理字段冲突；自定义名称不会默认被官网覆盖。

图片辅助存在本身不阻止删除无关模型。删除当前辅助模型时，可选择另一真实图片模型、关闭辅助并删除，或取消删除；旧兜底目标同时处理，共享别名与其他使用引用仍需解决。自身能力／档位可明确清理。完整操作备份，可恢复本次目录操作；配置版本或会话覆盖已变化时拒绝覆盖，包括重启导致旧 revision 不匹配的情况。

## 别名删除与视觉清理

从 0.9.0 起，在“别名与兜底”点击删除后，先预览全部引用，包括界面原先隐藏的旧主模型和旧视觉兜底。每项明确替换或清除，解决后勾选本组并“应用别名删除及引用修改”；不删除候选真实模型。旧主模型清除后，未启用新 AUTO 的旧入口使用宿主默认模型；启用 AUTO 的必填档及宿主默认只能替换。修改完整备份，可在同一服务生命周期恢复，后续配置变化会阻止覆盖恢复。

“视觉”页在辅助关闭时仍展示当前目标及旧视觉兜底，并提供明确清除入口。清空当前目标且仍有旧兜底时会确认一起清除，避免下拉显示未设置却暗中使用旧模型；无关当前视觉模型保留。失效选项显示原值及原因。别名删除应用前，其他插件草稿需先保存或放弃并重新预览。

## AUTO 与 Subagent

AUTO 只评估本轮**主任务**。插件用独立评估模型看最新请求和有限的近期上下文，返回任务等级与理由，然后选择兼容的执行模型。本轮工具循环保持该选择；下一轮用户消息重新评估。评估器不能调用工具，也不会执行任务。评估失败或超时 10 秒时使用常规档；候选能力不符时优先尝试更高档，没有兼容候选则报错。评估器看不到图片内容，图片能力由执行模型目录约束。

Subagent 是 DSH 原生机制。主 Agent 可以不创建子 Agent，也可以创建不限于固定角色名称的多个任务。普通 `subagent` 可选择不同模型和推理强度，并使用宿主的后台运行与结果通知；`subagent_fork` 继承父模型。子 Agent 不会再次触发 AUTO 评估。从 0.10.0 起分工偏好已停用，不再注入提示。

## 旧分工偏好清理（0.10.0）

设置页只保留“模型、别名与兜底、AUTO 自动选模型、视觉、日志”。历史分工偏好不再执行，也不会阻止模型或别名删除；启动和普通保存不自动删除旧数据。

AUTO 页若有已保存旧偏好，会显示“旧分工偏好已停用”。先保存或放弃其他草稿，点击“预览清理”，明确勾选后“应用清理”；取消不写设置。仅删除旧偏好，保留旧主模型、视觉兜底和官方子 Agent 设置。完成后可通过“恢复最近操作”恢复原值，恢复后的偏好仍停用；后续配置变化会阻止覆盖恢复。清理不调用 LLM。

## 常用场景

- **日常聊天与复杂编码混用**：简单档配轻量模型，常规档配日常模型，复杂档配代码／推理模型。日志可查看任务等级、实际模型和选择理由。
- **同一入口有备用模型**：创建别名，按优先顺序加入候选。每个候选分别设定真实推理档位；已有输出或工具操作后不会换模型重做任务。
- **图片与多 Agent**：主模型支持图片时原生处理；不支持时可开启视觉辅助，将图片交给辅助模型理解。并行调研或代码审查由主 Agent 使用原生 Subagent，模型范围到 DSH 官方设置配置。

## DeepSeek 官方资料

“模型”页使用本次预览的临时资料入口，默认 [DeepSeek 文档首页](https://api-docs.deepseek.com/zh-cn/)。可选择分析模型公开的推理档位；留空使用模型默认，不自动选择 low。每轮分析时限默认 180 秒，可临时填写 30–600 的整数秒，包含推理和输出；分析中显示本轮已用时间。网址、分析模型、档位和时限不保存，无需点击“保存设置”。点击“刷新并预览”重新读取网页，由独立分析模型根据原文识别当前 API model name；未选择时使用宿主默认模型，绕过 AUTO 和别名。最多读取六页、调用三轮 LLM，可取消；页面显示模型清单、证据、差异和预计数量，不固定模型数量。

新增、更新和无冲突迁移默认勾选；没有替代关系的移除需手动选择，有引用或用户设置冲突时阻止操作。若其他标签页有插件草稿，应用前可保存或放弃并重新预览；本次分析参数不属于该草稿；完整迁移插件、宿主和未来会话引用，保留凭据、输出上限及未知字段，备份后可恢复。失败或资料不完整不提供可应用预览；恢复遇到后续编辑会拒绝覆盖。分析会产生 LLM 用量，需要当前环境已配置可用凭据。详见 [规格](docs/SPEC.md)、[架构](docs/ARCHITECTURE.md#llm-官方同步契约) 和 [配置](docs/CONFIG.md#llm-官方同步配置)。

## 常见问题

- **为什么 AUTO 没有创建子 Agent？** AUTO 只选主模型。是否拆分由主 Agent 根据任务决定；原生 Subagent 的模型范围也要单独开启。
- **说“继续”会降到简单档吗？** 评估会带入有限的近期上下文，信息不足时按常规档处理。
- **配置何时生效？** 插件设置对后续请求生效。原生 Subagent 模型范围修改对**新会话**生效；安装或更新插件代码后需重启 DSH。
- **验证失败是否代表模型不支持？** 网络错误、取消和一次拒绝都不能直接改写能力资料。先核对 Provider 声明、模型 ID 和来源，再决定是否手动修改。
- **旧配置怎么办？** v1/v2 启动时迁移为 v3，保留模型、别名、视觉和旧主模型。新 AUTO 未启用前仍使用旧固定主模型，不增加评估调用。
