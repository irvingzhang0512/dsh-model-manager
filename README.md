# DSH 模型管理（dsh-model-manager）

模型**已经能在 DSH 里调用之后**，用这个插件做四件事：

1. **补能力声明**——模型其实能收图，但 DSH 只声明了文字，就在面板里改掉并验证；
2. **配别名与推理档位**——`@coding` 这类逻辑名绑定一串具体模型（按顺序兜底），把 fast/balanced/deep/max 映射到宿主真实档位；
3. **分派子任务**——主 Agent 把搜索/编码/审查/强分析/看图交给不同模型；
4. **视觉副驾**——主模型不支持图片时，先把图交给视觉模型，把结论当文字带回主模型。

调用是否按预期发生，可以在「日志」里逐条核对。

> 它**不**负责：导入模型、管理 API Key、替代 DSH Provider、重新实现 Agent Runtime。模型从哪来（Coding Plan / arkcli / 原生 Provider）与本插件无关。
> 未实现/未验收边界见 [docs/V1-COVERAGE.md](docs/V1-COVERAGE.md)；配置字段见 [docs/CONFIG.md](docs/CONFIG.md)；内部契约见 [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md)。

## 1. 五分钟上手

前提：DSH（web profile）已能正常对话，模型已在 DSH 里可用；Node ≥ 22。

1. **打开面板**：`设置 → 模型管理`（左侧设置分区里的「模型管理」）。
   默认停在「模型」标签，列出的是**宿主已经加载**的模型。刚导入的模型看不到 → 点「刷新目录」（不必重启 DSH）。
2. **建别名**：切到「别名与推理配置」→ 输入 `fast` 之类的小写名字 → 「添加别名」→ 在卡片里「添加候选」选具体模型。
   候选**按顺序**尝试，第 1 个是主选，后面是失败后的 fallback；别名至少要有 1 个候选才能保存。
3. **配推理档位**：同一页下方「推理档位映射」，给要用的模型把 `fast / balanced / deep / max` 各映射到宿主公开的**实际档位**（下拉里只有真实档位；留空表示这个档位不可选）。
4. **选模式并绑模型**：切到「Manual/Auto」。
   - `Manual`：主 Agent 用 **manual** 行（目标模型 / 思考 / 推理档位 / 输出上限）。
   - `Auto`：主 Agent 用 **auto** 行，并在下面「Auto 子 Agent 角色」里勾选启用 search / coding / review / strong / vision 各自的目标模型。
   - 「目标」填 `@别名` 才会走 fallback 链；填具体模型就只有它一个。
5. **验证**：切到「验证」→ 选模型 + 类型（文字 / 图片 / 工具 / 推理档位）→「验证一次」。
6. **保存**：页面底部（滚动时始终可见）的「保存设置」。有未保存修改时旁边会显示「● 有未保存的修改」，无修改时按钮为灰色不可点。保存后立即生效（下一次请求用新配置，不用重启 DSH）。
7. **回会话**：输入框左下角出现 `模型管理 · manual` 的折叠控件，展开可做本轮/本会话的临时覆盖（见 §3）。

**怎么知道已经生效**：DSH 的模型选择器里会多出一个 Provider「模型管理」，模型名形如 `模型名 · 原 Provider` 或 `@别名`；会话切到它（或输入区控件点「应用」）就走插件的路由。每次受管理调用的记录在「日志」标签。

## 2. 面板逐页说明

### 模型
- 顶部筛选：**Provider 下拉 + 模型名/ID 文本框**，两者同时生效，右侧显示「匹配 M / 共 N 个模型」，无匹配时有空状态提示，一键「清除筛选」。同一筛选条件也决定「验证」页批量验证的范围。
- 「刷新目录」重新读取宿主已加载模型：按钮显示「刷新中…」，完成后弹出提示并给出**数量变化**（如「新增 1、移除 0」）。所有操作结果都以右下角浮动提示（toast）反馈，不再只写在页面底部。
- 每张卡片显示宿主声明：**原生图片 / 上下文 / 默认输出**，以及已有验证证据（`类型: 状态 / 行为`，配置改过后标「已过期」）。
- **AI 探测能力**：对单个模型发一次**真实**图片探测请求（消耗 token），按结果给出可写入的结论。探测完成会弹出**居中建议对话框**，逐项显示「当前值 → 建议值」「置信度」「依据」，高置信项默认勾选，确认后「应用选中项」。批量入口「AI 探测当前筛选（N 个）」按当前筛选逐个探测，只自动写入高置信结论，并显示进度。
  - **宿主声明为「不支持」的模型也能测**：宿主会把发送前的图片替换成文字占位，所以插件会先把该模型的宿主图片声明**临时提为「支持」实测，测完立即恢复原声明**——模型亲口确认看到图（答对红色）才给出高置信「支持」结论。
  - 规则：图片答对探测图颜色 → 高置信建议「宿主原生图片=支持 + 插件图片声明=支持」；图片被拒或答错 → 低置信建议「插件图片声明=不支持」。**网络错误与取消不产生任何建议**，只留下验证证据。
  - 不探测工具调用，也不猜测上下文容量、最大输出和推理档位：工具调用可直接用「验证」标签手动验证；容量与档位无法由一次请求证实，仍需手工填写或由宿主元数据提供。
  - 提权实测的几秒窗口内该模型声明是临时的；探测失败或恢复失败都会明确提示，恢复失败时请到模型卡片核对「宿主原生图片」当前值。
- **保存到宿主**：把 `原生图片 / 上下文容量 / 模型最大输出` 精确写进宿主 `llm-pi-ai` 设置——**这一步才是让 DSH 真正按图片处理请求**。按钮灰掉时右侧会说明原因（该 Provider 未公开可写模型字段，或模型不在 Provider 的可编辑清单里）。
- **清除…覆盖**：删掉上述三项的宿主覆盖、回到宿主默认；只有该 Provider 没有显式模型清单时才可用。
- **插件图片声明**：只影响插件自己的路由判断（走原生还是走视觉副驾），不改宿主声明。

> 记住这条区别：**让 DSH 能收图 = 保存到宿主**（或 AI 探测建议里的「宿主原生图片声明」）；**让插件按图片走某条策略 = 插件图片声明**。

### 别名与推理配置
- 别名名字规则：小写字母开头，可含数字、`_`、`-`；不能重名，不能嵌套别名（候选只能是具体模型）。
- 「添加候选 / 移除 / 删除」维护有序候选列表；顺序即 fallback 顺序。
- 推理档位映射**按 Provider + 模型隔离**：两个 Provider 下的同名模型互不影响。

### Manual/Auto
- 这一页决定**走「模型管理」入口的会话**实际用哪个模型与推理参数；没走入口时本页不生效。会走入口的情形：DSH 模型选择器选了「模型管理」下的条目、输入框「模型管理」控件点过「应用」、或开启了视觉辅助。
- 「模式」决定主 Agent 用哪一行：Manual → `manual` 行，Auto → `auto` 行；两行字段相同，可当成两套整套切换的方案。
- 每行的字段：
  - **目标模型**：`跟随宿主／未设置` = 插件不指定模型；也可选具体模型或 `@别名`。
  - **思考**：`思考继承 / 思考自动 / 关闭思考`。宿主只公开推理档位、没有独立 Thinking 开关，所以「关闭思考」映射为模型公开的 `off` 档位，**只有模型公开该档位时才可选**；选它时推理档位只能是 `auto`。
  - **推理档位**：`继承上层设置 / auto / fast / balanced / deep / max`；非 auto 的档位必须先在「别名与推理配置」里映射过，否则请求会报「未配置 X 档位」。
  - **输出上限**：本次请求的 `maxOutputTokens`，留空表示不限。
- **子 Agent 角色（委派分工）**：`search / coding / review / strong / vision` 五个角色可被主 Agent 委派（启用 + 绑定模型后才会出现在模型可见的角色清单里），与当前 Manual/Auto 模式无关。表里的 `main` 行不参与委派（界面中复选框禁用），主 Agent 由上面的 manual/auto 行决定。

### 视觉
- **启用视觉辅助** + **策略**四选一：`Native First`（默认，主模型能看图就走原生）/ `Sidecar First` / `Native Only` / `Sidecar Only`。
- **视觉模型**：只列出宿主声明支持图片的模型，也可以填 `@vision` 别名。
- 效果：主模型保持编码能力不变，图片先由视觉模型理解，结论以文字回到主模型。

### 可靠性
- **最多实际尝试**（1–3，默认 3）、**网络失败重试一次**、**允许推理参数被拒时降级**（默认关）。
- **上下文溢出专用候选**：只在上下文溢出时启用；「添加长上下文候选」会自动挑当前上下文最大的模型。
- 已知行为：认证错误不会切同 Provider 的另一个模型；429 会临时冷却；本轮的显式覆盖参数不会被静默降级；已经产生的输出不会重播。

### 验证
| 类型 | 做了什么 | 能证明什么 |
|---|---|---|
| 文字 | 发一条「只回答 OK」 | Provider 可调用、基础参数正确 |
| 图片 | 发一张内置纯色小图并问颜色，答案里核对「红」 | 模型**真的看懂了图**（行为 observed / not-observed） |
| 工具 | 附一个探针工具，看模型是否真的发起调用 | 工具调用可用 |
| 推理档位 | 用当前 Manual 配置映射出的档位发一次请求 | 只能证明参数被接受，`behavior` 恒为 unknown，不代表内部推理强度变化 |

- 「批量验证当前筛选（N 次）」：串行发送、先弹确认、可「取消批量验证」。
- 结果状态：`accepted / rejected / network-error / cancelled`。
- 配置或模型声明变化后旧证据会标「已过期」，需要重新验证。

### 日志
- 「刷新日志」读取最近 200 条受管理调用记录（主请求 / 委派 / 视觉）。
- 含 `key / secret / prompt / image / credential / bytes` 字样的字段不会写入。
- 保留策略：7 天、单文件上限 50 MB。

### 底部操作条（保存设置 / 重新加载）

固定在面板底部，滚动任何标签页都能看到，并显示当前是否有未保存的修改：

| 按钮 | 作用 | 说明 |
|---|---|---|
| **保存设置** | 把**全部标签页**的插件配置（别名、推理档位、Manual/Auto、角色、视觉、可靠性）一次写入 DSH 设置 | 只保存与已保存版本不同的内容；没有修改时按钮为灰色。保存后下一次请求生效，不需要重启 DSH。 |
| **重新加载** | 放弃未保存的修改，重新读取**已保存**的配置 | 有未保存修改时会先弹确认，避免误丢。配置在别处被改过（保存时报冲突）时，用它取回最新版本。 |
| **保存到宿主**（在模型卡片内） | 把某个模型的 `原生图片 / 上下文容量 / 最大输出` 写入宿主 `llm-pi-ai` 设置 | 与「保存设置」是两件事：这一项改的是**宿主声明**，立即生效，不受「保存设置」影响。 |

## 3. 输入区的「模型管理」控件（临时覆盖）

位置：输入框左下角，折叠标题为 `模型管理 · 手动/自动`，展开后顶部有一句用途说明，可设：

模型 / 思考 / 推理档位 / 输出上限，下方第二行选**范围**（`仅下一条消息` 或 `本会话一直有效`）+「应用」「清除」。

- 用途：给**当前会话**临时换模型或推理参数，不改全局设置；优先级**本轮覆盖 > 会话覆盖 > Manual/Auto 全局**。
- 「仅下一条消息」回合结束自动清除；「本会话一直有效」在该会话内一直有效。
- 点「应用」会立即把当前会话切到受管理入口；「清除」去掉覆盖。

## 4. 三个照着做的场景

**A. 模型其实支持图片，但 DSH 只声明了文字**
`模型` 标签 → 找到该模型 → 点「AI 探测能力」（真实发一次图片探测）→ 在建议清单里确认「宿主原生图片声明：未知 → 支持」→「应用选中项」→ 插件会写宿主声明并留下验证证据。
手工路径：`模型` 标签 →「宿主原生图片」选「支持」→「保存到宿主」→「验证」标签选类型`图片`「验证一次」→ 结果 `accepted / observed` 后，下一次请求就能直接收图。

**B. 给编码任务换模型，失败自动升级**
`别名与推理配置`：建 `@coding`，候选 1 = 目标模型，候选 2 = 备选；给候选映射 fast/balanced/deep 档位。
`Manual/Auto`：启用 `coding` 角色、目标填 `@coding`。之后主 Agent 委派编码任务时会按候选顺序尝试，失败可带 `upgrade_tier` 提档或换更强角色，全过程可在「日志」核对。

**C. 主模型看不懂图，也要能看图**
`视觉` 标签：勾选「启用视觉辅助」，策略 `Native First`，视觉模型选一个声明支持图片的模型（或 `@vision`）→ 保存。
之后往会话里贴图，主模型会通过看图工具查询原图结论，继续用自己的模型完成编码；追问同一张图会命中视觉缓存。

## 5. 插件注入的两个模型工具

主 Agent 会自动使用，不需要手工配置；理解它们有助于看懂日志：

- `model_manager_delegate(role, task, expected_result, upgrade_tier?)`——按角色委派独立任务。只有在角色已启用且绑定了有效模型时可用；同时最多 3 个子任务，同一工作区的 `coding` 只能 1 个。
- `model_manager_inspect_image(attachment_id, question, region?)`——查看当前会话内的图片附件原图。`region` 是归一化的 `x,y,width,height`（四个数都在 0–1，例如 `0.25,0.25,0.5,0.5`），插件会用本地 `sharp` 裁剪后再问，原图仍保留在会话里。

## 6. 配置与数据放在哪

- **设置**：DSH 设置命名空间 `dsh-model-manager`，`version: 1`；面板保存即写入，下一次请求生效。
- **运行数据**（按 profile 隔离）：`%DSH_HOME%\profiles\<profile>\data\dsh-model-manager\`
  - `verification.json` 验证证据；`overrides.json` 会话/本轮覆盖；`vision-cache.json` 视觉结果缓存（7 天、最多 1000 条）；`calls.jsonl` 调用日志。
  - 均以 `.tmp` + `.bak` 原子替换写入，缓存损坏时从备份恢复。
- **宿主原生字段覆盖**写在 `llm-pi-ai` 设置里，与插件配置分开保存。

## 7. 常见问题

| 现象 | 处理 |
|---|---|
| 面板里看不到某个模型 | 宿主还没加载它：先在 DSH 里配好 Provider/模型，再点「刷新目录」。 |
| 「保存到宿主」是灰的 | 看右侧原因：该 Provider 未公开可写模型字段，或模型不在 Provider 的可编辑清单里。 |
| 不确定某个模型支不支持图片 | 用模型卡片上的「AI 探测能力」：发一次真实图片探测请求，按结果给出建议并要求你确认；不要凭猜测手填。 |
| 探测没有给出建议 | 说明这次请求没有形成可用证据（网络错误、被取消、临时提权宿主声明失败，或图片行为没结论）。具体原因看对话框里的说明或「验证」标签的证据详情，排除后重试。 |
| 「保存设置」点不动 | 表示当前没有未保存的修改（已保存版本与草稿一致）。改了任意字段后按钮会变为可点，旁边出现「● 有未保存的修改」。 |
| 提示配置冲突、请重新加载 | 设置被别处改过：点「重新加载」拿最新版本再改（会先确认是否放弃未保存修改）。 |
| 报「未配置 deep 档位」 | 到「别名与推理配置」的推理档位映射里补上该模型的档位。 |
| 报「当前模型不支持图片，且视觉辅助不可用」 | 模型没声明图片能力，且没启用视觉辅助或没绑视觉模型。 |
| 会话好像没走插件 | 「目标」留空、未启用视觉、也没配推理档位/输出上限时，插件完全不插手；配一项即可，或在输入区控件点「应用」。 |
| 插件从界面消失、宿主路由 404 | web profile 的跨盘链接坏了（pnpm 10.17 已知问题）：在根仓库跑 `node tools/repair-web-links.mjs --check`，需要时去掉 `--check` 修复，再 `dsh plugin --profile web list`，最后重启 DSH。 |
| 改了代码要不要重启 | client 改动刷新浏览器（bundle 按 mtime 热加载）；host 改动需重启 DSH。 |

## 8. 安装与开发

```powershell
# 依赖与验证（A 型：TypeScript + tsdown + vitest；sharp 是运行时依赖）
npm install
npm run typecheck
npm test
npm run build          # 重建 lib/（host 与 client bundle）

# 链接到 web profile（跨盘路径见上方排错一行）
dsh plugin --profile web link F:\irving-dsh-plugins\dsh-model-manager
dsh plugin --profile web list        # 触发 bundle reconcile
# 首次加载插件需要重启 DSH；之后设置修改在下一次请求生效
```

- 依赖基线：Node ≥ 22，宿主 API 以本机 DSH `0.1.5-rc.2` 已公开的 `llm / settings / attachments / subagents / tools / webServer / systemPrompt` 服务为准（精确范围见 `package.json` 的 `peerDependencies`）。
- 文档分工：`docs/ARCHITECTURE.md` 契约与路由表、`docs/CONFIG.md` 配置字段、`docs/V1-COVERAGE.md` 覆盖与未完成项、`docs/CHANGELOG.md` 版本记录、`docs/REQUIREMENTS.md` 原始需求（只读）。
