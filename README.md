在 DSH 中配置模型参数、管理别名和备用模型、按任务自动选择主模型，并为文本模型提供视觉辅助。

## 能做什么

- 接入 DeepSeek 官方、火山 Agent Plan 和 OpenCode Go 的模型来源，预览后应用模型配置。
- 为现有模型调整实际支持的推理参数、上下文与输出上限，区分资料建议和调用验证结果。
- 用一个别名管理多个有顺序的候选模型，在故障时重试、切换和冷却恢复。
- 开启 AUTO 后，按任务规则从你保存的范围选择主模型。
- 配置视觉模型先理解图片，让文本模型结合观察继续处理任务。

## 安装

当前本地版本 **0.2.1-rc.2+rev.1**，适配 **DSH Desktop 0.2.1-rc.2**。使用 OpenCode Go 来源时，还需安装并启用 **dsh-opencode-go 0.1.24**；其他来源不依赖它。实际宿主要求见 [package.json](package.json)。

截至 2026-10-18，[公开源码仓库](https://github.com/irvingzhang0512/dsh-model-manager)默认分支包版本为 **0.3.0**，本页版本尚未公开推送或发布。先向维护者获取对应版本的完整预构建 `.tgz`，目前没有本版公开下载链接。

1. 打开「插件 → 添加插件 → 安装第三方插件」，填写安装包的本机绝对路径。
2. 核对包名 `dsh-model-manager` 和版本 `0.2.1-rc.2+rev.1`，启用后按提示重启 DSH。
3. 在「插件 → Irving · 模型增强 → 模型增强」确认出现来源、模型、别名、AUTO、视觉和日志六个标签。

此前兼容验证见 [升级记录](docs/DSH-UPGRADE-20261017.md)，完整功能验收见 [0.13.0 验收](docs/VERIFICATION-0.13.0.md)。

## 配置

第一次使用只需准备一个来源；已有模型的用户可先查看、调整参数。AUTO 和视觉辅助默认关闭，按需要分别开启。

| 来源／能力 | 如何准备 |
|---|---|
| DeepSeek 官方 | 在来源页输入 Key，点击「先保存凭据，再读取模型」，检查预览后应用 |
| 火山 Agent Plan | 明确选择本机 ArkCLI 的套餐 Profile，按需完成账号授权，再配置实际调用 Key；账号查询与调用凭据分开 |
| OpenCode Go | 从「账号与来源设置」进入原插件，保留其账号、用量和目录管理 |
| 别名与兜底 | 手动添加候选并排序，保存后在模型选择器选择对应别名 |

密钥交给 DSH 凭据服务，插件保留引用。插件各页用「保存设置」保存草稿，模型卡的「保存到宿主」和来源导入有独立预览与保存流程。完整参数及迁移见 [配置指南](docs/CONFIG.md)。

## 第一次使用

1. 打开「模型来源」，准备一个可用来源，读取模型列表。
2. 检查预览中的连接、模型和参数。已有不同值或最大输出上限需要明确选择，再点击「应用选中配置」。
3. 在「模型」页核对实际名称、来源和参数，到会话模型选择器选中导入的模型。
4. 发送一句普通问题，确认能收到回答，并在日志中核对实际调用目标。真实请求会产生对应服务的用量。

取消导入不会撤回已经单独保存的凭据；刷新来源不会自动删除下架模型。

## 常用操作

| 想做什么 | 怎么做 | 结果 |
|---|---|---|
| 调整模型参数 | 在模型页修改该模型实际支持的字段，预览后保存到宿主 | 后续调用采用保存的参数 |
| 设置备用模型 | 在「别名与兜底」添加候选、排序并保存 | 选择该别名时按候选顺序尝试 |
| 按任务选模型 | 在 AUTO 页设置评估模型、简单／常规／复杂目标及规则，开启并保存，然后在会话选择 `AUTO` | 每轮按保存范围选择主模型 |
| 给文本模型看图 | 在视觉页开启辅助，选择原生支持图片的模型或对应别名 | 先理解图片，再将带来源的观察交给主模型 |
| 核对能力 | 使用单次「验证调用」 | 产生一次真实请求，单独记录验证证据 |

## 使用边界

- 别名候选由你维护。临时故障每候选最多尝试五次，失败的半段回答丢弃，成功后提交输出；已完成的工具不会因换模型重做。
- 冷却默认：重试耗尽一分钟、限流五分钟、额度不足一小时；服务端有效等待优先。到期由下一轮真实请求尝试首选，不在后台自动探测。
- AUTO 默认关闭，开启后还需在会话选择 `AUTO`。每轮最多评估一次，十秒超时采用常规档；没有满足能力条件的目标会明确失败。
- DSH 原生 Subagent 独立负责拆分与子模型选择，子任务不会再次触发 AUTO；fork 延续父任务实际模型。
- 自动视觉失败会阻止主请求并报错，不应把文本模型声明为原生支持图片。关闭自动理解仍可按现有工具路径手动处理。
- 网页同步、智能补全和验证可能使用网络及模型，资料建议不等于实测通过。未确认的批量测试方案不属于本版。

## 常见问题

### 开了 AUTO，为什么模型没有变化

确认 AUTO 设置已保存，并在当前会话模型选择器选中 `AUTO`。直接选择具体模型会使用该模型；子任务也有独立的宿主选择规则。

### 删除或改名提示仍被引用

查看预览列出的别名、AUTO、视觉及宿主引用，明确选择替换或清理后再应用。不要直接删除配置文件中的条目。

### 刷新目录后，旧模型为什么还在

刷新不会自动删除模型。先核对来源、引用和实际可用性，再通过模型管理的删除流程处理。
