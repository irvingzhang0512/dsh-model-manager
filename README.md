# dsh-model-manager

当前兼容升级与验证见 [Desktop 0.2.1-rc.2](docs/DSH-UPGRADE-20261017.md)。历史版本验收仍保留，不代表本版已公开发布。

在 DSH Desktop 中集中接入模型来源、配置备用模型、按任务选择主模型，并为文本模型提供图片辅助。

## 安装与入口

0.13.1 适配并限定 DSH Desktop **0.2.1-rc.2**。运行依赖与宿主接口以 package.json 为准，Git 安装携带完整 lib 产物，不在安装时编译。本版当前为本地固定提交交付，尚未推送或发布到 npm／市场，不把公开仓库默认分支当成本版安装来源。验证范围见 [验收记录](docs/VERIFICATION-0.13.0.md)。

安装并启用后重启 Desktop，在“插件 → dsh-model-manager → 模型管理”打开六个标签页。模型选择器中的受管理具体模型、`@别名` 和 `AUTO` 通过本插件调用；直接选择来源模型可以绕过主模型选择。

## 第一次使用

1. 打开“模型来源”，选择 DeepSeek 官方、火山 Agent Plan 或 OpenCode Go。
2. DeepSeek 输入 Key，点击“先保存凭据，再读取模型”。火山先明确选择本机 ArkCLI 的套餐 Profile，再输入套餐调用 Key；账号查询和调用 Key 分开管理。需要登录时点击“连接火山账号”完成官方授权。OpenCode Go 使用“账号与来源设置”进入原插件，保留其多账号、用量和目录同步功能。
3. 检查模型、连接和字段预览，点击“应用选中配置”。已有不同值和最大输出上限需要明确选择，刷新不会删除下架模型。取消导入保留已经独立保存的新 Key。
4. 到“模型”页核对来源声明、实际推理档位和容量，再在模型选择器选择所需模型，发送一句日常问题。日志可查看实际调用目标；“验证调用”会单独发出真实请求并产生用量。

Key 交给 DSH 凭据服务，管理器只保存引用。各来源实际公开的推理档位分别使用，不把任务复杂度或七档兼容声明当作后端一定具有七种强度。

## 备用模型与自动恢复

在“别名与兜底”手动添加候选并排序，同模型跨来源或不同模型均可。候选不自动增删，各自保留真实推理档位。网络、超时、临时服务故障每候选最多调用五次；失败的半段回答丢弃，成功后提交完整输出，已完成工具不会重做。

重试耗尽默认冷却一分钟，限流默认五分钟，额度不足默认一小时；服务端有效等待优先。三项时间可修改。凭据错误需要更换凭据或手动恢复，图片／上下文／参数不匹配只跳过本次。冷却期间使用后续候选，到期由下一轮真实请求尝试首选，不后台探测。本轮工具循环固定成功候选；“立即重新尝试首选”仅重置状态。

## AUTO 按任务选主模型

在“AUTO 自动选模型”配置评估模型和简单、常规、复杂三档目标，可选择具体模型或别名。需要时增加编码、写作、调研、分析、通用规则，限定复杂度并排序；采用第一个满足条件的规则，未匹配时用三档配置。可先生成自动推荐草稿，修改后保存。

开启并保存后，在模型选择器选 `AUTO`。每轮先检查图片、工具、上下文和参数条件，再最多评估一次；十秒超时采用常规档。能力不足向更高档寻找，仍无可用目标则明确失败。运行只使用用户保存的范围。

DSH 原生 Subagent 独立负责拆分任务和选择子模型，子任务不会再次触发 AUTO；fork 延续父任务实际模型。火山自身路由可作为普通候选。

## 图片辅助

“视觉”默认关闭辅助；开启后选择原生支持图片的视觉模型或全原生图片别名。“原生优先”让能看图的主模型直接处理；文本候选则先由视觉模型理解原图，再把带附件编号和实际来源的观察写入会话。新图片、工具返回图片和历史追问均覆盖，相同图片与问题在会话内缓存。

原图保留，可继续调用看图工具追问或裁剪。自动辅助失败会阻止主请求并明确报错。关闭“自动理解图片”可保留原来的手动工具路径；“仅原生”限制仍然有效。不要批量把文本模型声明为原生支持图片。

## 保存与迁移

“保存设置”保存插件各页草稿；模型卡“保存到宿主”和来源导入写回实际所有者，使用独立预览与备份。切换标签或刷新目录保留未保存草稿，并发编辑拒绝覆盖。安装代码后需重启；普通原生参数按宿主生命周期重挂载，实时字段用于后续请求。

v1–v3 读取时幂等归一为 v4，保留有效主模型、视觉目标、逐候选档位、未知字段和历史受管理 ID。已退役图片覆盖、子模型偏好和别名旧策略仍走明确的独立清理／备份／恢复，不因升级静默删除。可读 ID 使用 Provider＋Model 复合标识。

现有模型新增／改名／删除、官方网页同步、参数智能补全和单次能力验证继续提供。网页分析及验证会产生真实调用，用前核对来源与凭据；资料建议与实测证据分开展示。
